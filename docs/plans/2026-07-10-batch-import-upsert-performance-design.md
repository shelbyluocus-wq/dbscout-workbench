# 批量导入更新、提速与取消设计

## 问题结论

本次真实文件证明“空单元格”不是全表失败的主因：`actcontinuercencmodelprop.xlsx` 有 565 行、15 列且没有空白格，但 565 行全部失败。当前批量导入只调用 `insert_row`，目标表主键已存在时会逐行返回“主键重复”。同时每行都会独立跨越前端、Tauri、表结构读取和数据库写入，31,081 行会产生约三万次串行命令调用。导入状态也没有取消标记，因此界面只能等待。

## 目标行为

- 主键不存在：新增该行。
- 主键已存在：只更新 Excel 已映射的非主键字段。
- Excel 未提供或按规则省略的字段：更新时保持数据库原值，新增时使用默认值或 NULL。
- 单行失败：记录来源文件、工作表、行号、字段、原值和原因，不阻塞后续行。
- 点击取消：当前批次结束后停止，不回滚已经成功的批次。

## 批处理边界

前端将每张表的有效草稿按 100 行分块，调用新的 `import_rows` Tauri 命令。后端在每个命令中只读取一次表结构，然后处理这一批行并返回逐行结果。这个粒度能显著减少 IPC 和重复 schema 查询，同时把取消等待限制在一个短批次内。

响应汇总 `inserted`、`updated`、`unchanged` 和逐行 `errors`。进度以已返回的行数推进；取消后状态为 `cancelled`，结果中保留已成功表和错误日志。

## 后端写入与审计

新增 `batch_import.rs` 承担批量导入的 MySQL SQL 规划与执行，`commands.rs` 只负责会话解析和命令注册。

每行先用完整主键查询是否存在：

- 不存在时生成 INSERT，并生成按主键 DELETE 的反向 SQL。
- 存在时比较 Excel 映射字段，生成一次多列 UPDATE，并生成恢复旧值的反向 UPDATE。
- 值完全相同则返回 unchanged，不写数据库也不创建审计。

每次实际写入继续创建和落定一条审计记录，保证现有回滚中心能够处理批量导入。后端单批最多接受 100 行，避免超大请求和长时间不可取消。

## 前端交互

导入中显示“取消导入”按钮；点击后变为“正在取消…”，不再启动下一批。导入完成文案显示新增、更新、未变化、失败和跳过数量。错误日志导出沿用现有 XLSX 功能。

## 验证

- 后端测试覆盖：新增、已有主键更新、未映射字段保持、无变化、单行错误和 100 行上限。
- 前端测试覆盖：按 100 行分块、结果汇总、取消后不发送下一批、取消状态和按钮。
- 使用用户提供的真实 Excel 验证文件解析结果不再因空值或重复主键被整表拦截。
- 运行相关 Node 测试、Rust 测试、生产构建和真实浏览器检查。
