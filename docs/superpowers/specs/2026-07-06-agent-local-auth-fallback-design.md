# Database Agent 本机配置优先与免登录设计

## 目标

Database Agent 启动时优先复用电脑上已经可用的 Claude Code 配置。电脑上没有可用配置时，用户只需要在黑猫界面填写 API Key、请求地址和可选模型即可使用；产品不再展示或要求执行 `/login`。

## 配置优先级

1. 用户在黑猫界面填写的 API Key、Auth Token、请求地址或模型属于显式覆盖，优先级最高。
2. 没有显式覆盖时，Sidecar 使用电脑默认的 Claude Code 配置目录，让本机已有的认证、请求地址和模型设置自然生效。
3. 两者都不可用时，将 Claude Code 的“未登录”结果转换成黑猫自己的“需要配置”状态，显示现有的接入配置页。

显式覆盖模式继续使用黑猫隔离的 Claude 状态目录，避免本机设置意外覆盖用户刚在界面输入的请求地址。复用本机模式不设置隔离目录，但会继续使用黑猫自己的工作目录保存会话，因此不会改变数据助手的会话列表位置。

## 用户体验

- 已配置 Claude Code 的电脑：直接发送问题即可，无额外设置。
- 未配置 Claude Code 的电脑：首次发送后进入黑猫接入配置页，填写 API Key 和 Base URL 后即可重试。
- 认证缺失时不显示英文 `Not logged in · Please run /login`，而是显示中文配置提示。
- 原有数据库只读自动放行、写入审批和计划模式不变。

## 错误处理

Sidecar 只把明确的 Claude Code 登录缺失错误归类为 `auth_required`；网络、限流、模型名错误等仍保留为普通错误，避免把真实服务故障误判成未配置。

## 验证

- 单元测试证明：没有界面凭据时不注入隔离配置目录；存在 API Key/Token 时继续隔离。
- 单元测试证明：`Not logged in` / `Please run /login` 会转换为 `auth_required`，其他错误不受影响。
- 前端单元测试证明：收到 `auth_required` 后切换到接入配置页、清除启动态，并允许填写配置后重新启动。
- 运行 Sidecar 测试、前端 Agent 测试、Rust Agent 测试、生产构建，并在真实界面验证两条入口。
