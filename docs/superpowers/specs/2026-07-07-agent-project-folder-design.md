# Database Agent 项目文件夹只读接入设计

## 目标

Database Agent 支持添加本机项目文件夹。添加后，用户可以像在 Claude Code 中一样让 Agent 阅读项目文件、搜索代码、理解项目结构，并且界面始终清楚显示“当前正在使用哪个项目”。第一版只做只读接入：Agent 可以列目录、搜索、读取文件，但不能修改文件、删除文件或执行项目命令。

## 已确认决策

- 第一版项目文件夹能力为只读。
- 支持添加多个项目文件夹，但同一时间只有一个“当前项目”。
- 采用“项目入口放在 Agent 顶部”的体验，而不是把项目选择藏进设置面板。
- 保留现有 Agent SDK 稳定工作目录，避免破坏会话历史；项目文件夹通过受控只读工具接入。

## 非目标

- 不在第一版提供项目文件写入、重命名、删除、创建文件等能力。
- 不在第一版提供项目命令执行、测试运行、依赖安装或终端能力。
- 不做完整 IDE 文件树；项目入口只负责选择、切换、状态提示和只读上下文接入。
- 不把数据库上下文和项目上下文绑定在一起；用户可以在同一个数据库连接下切换不同项目。

## 用户体验

### Agent 顶部项目入口

在右侧 Database Agent 顶部区域新增项目状态行，位于现有数据库上下文附近：

- 未添加项目：显示“未接入项目文件夹”，右侧为文件夹加号图标。
- 已添加项目：显示“项目：<文件夹名>”，并以悬浮提示或次级文案展示短路径。
- 当前项目：在项目列表中使用高亮圆点标识。
- 只读状态：在项目名旁显示“只读”小徽章，让用户知道 Agent 不会改文件。
- 项目不可用：如果路径不存在或权限不足，状态变为“项目不可用”，提示重新选择或移除。

图标继续使用现有线性 SVG 风格，不引入新图标库。项目入口使用“文件夹 + 加号/圆点”的组合：加号代表添加项目，圆点代表当前项目，警示态用现有错误色。

### 项目下拉面板

点击项目入口后打开轻量下拉面板：

1. 顶部展示当前项目名称、短路径、只读状态。
2. 下方列出已添加项目，点击即可切换为当前项目。
3. 提供“添加项目文件夹”按钮，调用系统文件夹选择器。
4. 每个项目提供“移除”动作；移除当前项目后，自动选择列表中的下一个项目，没有剩余项目则回到未接入状态。
5. Agent 忙碌时禁止切换、移除或添加项目，并提示“Agent 完成后可切换项目”。

### 对话中的项目认知

发送消息时，当前项目会作为本轮上下文传给 Agent。用户消息的本地展示也带项目标签，例如“项目：dbscout-workbench”，让历史对话能看出当时基于哪个项目提问。

切换项目不会中断当前会话，也不会重写历史消息。切换只影响下一次用户消息；Agent 正在输出时不能切换，避免一次回答里读取到不同项目。

## 架构

### 前端项目状态层

新增独立的项目上下文状态模块/组合函数，职责包括：

- 已添加项目列表。
- 当前项目 ID。
- 添加、移除、切换项目。
- 持久化到本地存储。
- 生成当前项目的展示名称、短路径、可用状态。
- 为 Agent 上下文生成稳定字段。

建议的项目对象形态：

```json
{
  "id": "canonical-path-derived-id",
  "name": "dbscout-workbench",
  "path": "E:/project/dbscout-workbench",
  "shortPath": "E:/project/dbscout-workbench",
  "available": true,
  "lastSelectedAt": 1783382400000
}
```

项目列表使用本地存储，不存进数据库连接配置。路径来自用户本机，只对本机应用有意义。

### 桌面文件夹选择层

Rust 侧新增项目文件夹相关命令，复用现有 `rfd::AsyncFileDialog::pick_folder()` 模式：

- `agent_pick_project_directory`：打开系统文件夹选择器，返回标准化项目信息。
- `agent_validate_project_directory`：校验持久化路径是否仍存在、是否仍是目录、是否可读取。

选择阶段只做轻量校验，不扫描整个项目，避免选择大型仓库时卡顿。

### Agent 只读文件工具层

Sidecar 新增一个只读 MCP server，例如 `dbscout-project`。它始终可以注册，但没有当前项目时工具返回“未选择项目”。工具读取 `currentContext.project`，因此同一稳定 Agent 会话可以在不同用户消息中使用不同当前项目。

第一版工具：

- `list_project_files`：列出当前项目内文件，支持相对目录、最大数量、默认忽略目录。
- `search_project_files`：在当前项目内搜索文本，返回文件、行号、匹配片段。
- `read_project_file`：读取当前项目内的单个文本文件，返回内容、大小、是否截断。

这些工具为只读工具，应像现有数据库只读工具一样自动放行。写入类 Claude Code 工具、Bash、Edit、Write 仍走现有审批规则，第一版不把它们用于项目文件夹。

## 安全边界

### 路径限制

项目工具必须把所有输入路径解析为当前项目根目录下的真实路径。以下情况必须拒绝：

- `..` 逃逸。
- 绝对路径指向项目外。
- 符号链接解析后指向项目外。
- Windows verbatim/UNC 变体绕过根目录校验。
- 空路径或非文本文件读取请求。

Rust 返回路径时做一次规范化；sidecar 在每次工具调用时再次校验。前端持久化路径不能被视为可信来源。

### 默认忽略范围

默认跳过大型或无关目录：

- `.git`
- `node_modules`
- `target`
- `dist`
- `build`
- `.tauri`
- `.venv`
- `coverage`

默认跳过明显敏感文件：

- `.env` / `.env.*`
- `*.pem`
- `*.key`
- `.npmrc`
- `.ssh` 目录

被跳过的敏感文件返回明确提示，不静默假装不存在。第一版不提供读取敏感文件的批准流；后续如要支持，需要单独设计“敏感文件读取审批”。

### 文件大小和结果数量

- `read_project_file` 设置单文件读取上限，超出时返回截断标记和提示，避免把“部分内容”伪装成完整文件。
- `search_project_files` 设置最大匹配数和最大扫描文件数，超出时提示用户缩小范围。
- 二进制文件返回“无法作为文本读取”，不把乱码塞进上下文。

## Agent 上下文

`AgentContext` 扩展项目字段：

```json
{
  "project": {
    "id": "canonical-path-derived-id",
    "name": "dbscout-workbench",
    "rootPath": "E:/project/dbscout-workbench",
    "shortPath": "E:/project/dbscout-workbench",
    "readOnly": true,
    "available": true
  }
}
```

Sidecar 的系统追加提示包含：

- 当前项目名称。
- 当前项目路径。
- 项目工具只读。
- 数据库问题优先使用 `dbscout-db`，代码/文档问题使用 `dbscout-project`。
- 不要承诺已经修改项目文件；当前能力只能读取和分析。

每轮用户消息也带简短上下文：

```text
DB Scout 当前上下文:
当前数据库: game_db
当前活动表: player
当前项目: dbscout-workbench (只读)
项目路径: E:/project/dbscout-workbench
```

## 错误处理

- 用户取消文件夹选择：不报错，保持原项目状态。
- 路径不存在：顶部显示不可用；发送消息时仍允许用户询问数据库，但项目工具会提示重新选择项目。
- 权限不足：展示“无法读取此项目文件夹”，建议重新选择有权限的位置。
- Agent 忙碌时切换项目：按钮置灰，不排队执行切换。
- 工具读取越界路径：返回安全错误，Agent 应解释只能读取当前项目内文件。
- 文件过大：返回部分内容和截断说明，并建议使用搜索或读取更小文件。

## 验证计划

### 前端单元测试

- 项目列表可以添加、切换、移除并持久化。
- 当前项目会被注入 Agent 上下文。
- Agent 忙碌时项目切换入口置灰。
- 项目不可用时 UI 显示明确状态。
- 用户消息能显示当时的项目标签。

### Rust 单元测试

- 文件夹选择命令返回统一字段。
- 路径标准化处理 Windows 普通路径、verbatim 路径和 UNC 路径。
- 持久化路径校验能区分不存在、非目录、不可读。

### Sidecar 单元测试

- `read_project_file` 拒绝 `..`、绝对路径逃逸、符号链接逃逸。
- 搜索和列表默认忽略大型目录。
- 敏感文件默认拒绝读取，并返回明确提示。
- 没有当前项目时，项目工具返回可理解的错误。
- 只读项目工具被自动批准，写入工具仍需要审批或被计划模式拦截。

### 手动验收

1. 启动黑猫，打开 Agent 面板。
2. 添加一个项目文件夹，顶部显示项目名和只读徽章。
3. 让 Agent 回答“这个项目的入口文件在哪里？”应触发项目搜索/读取。
4. 切换另一个项目后再提问，回答应基于新项目。
5. 重启应用后，项目列表和当前项目仍保留。
6. 请求“修改某个文件”时，Agent 明确说明当前项目接入为只读。

## 成功标准

- 用户能从 Agent 面板清楚看到当前项目。
- Agent 能读取和搜索当前项目文件，并把结果用于回答。
- Agent 不会读取当前项目外的文件。
- Agent 不会修改项目文件或运行项目命令。
- 项目切换、路径失效、文件过大等情况都有清楚反馈。
- 现有数据库助手能力、审批流、计划模式和会话历史不受破坏。
