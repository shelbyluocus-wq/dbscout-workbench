## 表设计页面优化

对 `TableDesignEditor.vue` 进行了全面的交互和视觉优化，共7项改进：

### 修改文件
- `src/workbench/components/TableDesignEditor.vue` — 重写组件

### 具体改动
1. **边框易读性**：将表格外容器阴影和单元格边框从 `var(--wb-line)`（极浅）提升到 `var(--wb-border)` / `var(--wb-border-strong)`，浅色模式下更易辨认
2. **列宽可调整**：每列表头右侧添加 6px 拖拽条，支持鼠标拖拽调整列宽，最小50px
3. **类型下拉 + 自动长度**：类型列改为 `<select>`，提供24种常见MySQL类型（INT/VARCHAR/BIGINT/DECIMAL/DATETIME等），选择后自动填充对应默认长度值（如 VARCHAR→255, INT→11, DECIMAL→10,2）
4. **默认允许NULL**：normalizeColumn 已默认 nullable=true；取消主键勾选时自动恢复允许NULL
5. **字段拖拽排序**：每行左侧添加 ⋮⋮ 拖拽手柄，支持HTML5 Drag API拖拽整行调整字段顺序
6. **主键放到第二列**：表头顺序调整为：字段名 | 主键 | 类型 | 长度 | 小数位 | 允许NULL | 默认值模式 | 默认值 | 备注
7. **备注放大窗口**：备注列添加放大按钮(⛶)，点击弹出对话框，上半部分编辑（支持Markdown）、下半部分实时预览，支持标题/加粗/斜体/代码/代码块/链接/图片/引用/列表/表格等Markdown语法

## 表设计保存提示与冲突反馈优化（第四批）

### 问题
用户把 VARCHAR 的 `name` 字段改成 INT 后点击「保存」，按钮变灰但没有任何提示，重新进入后发现未保存成功。根本原因是：有冲突时弹窗打开但确认按钮被 disabled，用户没看到冲突提示或不明白为什么不工作。

### 修改文件
- `src/workbench/components/TableDesignEditor.vue` — 保存/成功/冲突提示逻辑
- `src/workbench/workbench.css` — 成功提示、冲突横幅样式

### 具体改动
1. **页面主区域冲突横幅**：当 preview 有 conflicts 时，在表设计页面顶部显示红色醒目横幅「⚠️ 存在冲突，无法保存」，并说明「当前修改与表中已有数据不兼容」
2. **保存按钮 disabled + tooltip**：有冲突时「保存」按钮自动 disabled，hover 显示 tooltip「存在冲突，请先修正后再保存」
3. **点击保存自动提示冲突**：`handleSave` 调用 preview 后若检测到冲突，自动关闭弹窗并在页面主区域显示错误信息「检测到 X 处冲突，无法保存。请点击「预览修改」查看详情。」
4. **保存成功 toast**：`handleConfirmApply` 成功后显示绿色 toast「✅ 表设计保存成功」，4 秒后自动消失
5. **弹窗冲突提示更醒目**：冲突区域加粗边框、更大标题、红色文字，列表带序号
6. **按钮文字**：确认按钮拆分为 `v-if`/`v-else` 两个按钮，避免 Vue `{{ }}` 插值导致测试正则无法匹配
